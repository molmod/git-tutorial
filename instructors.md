# Information for instructors

The slides and the hands-on tutorials are built with a [StepUp](https://reproducible-reporting.github.io/stepup-core/) workflow,
defined in [`plan.py`](plan.py).
It compiles the slides into `slides.pdf` and `slides.html`
and renders the hands-on tutorials for each installment of the training.

## Hands-on tutorials

The tutorials are rendered from [Jinja](https://jinja.palletsprojects.com/) templates in
[`handson/.template/`](handson/.template/).
This includes the figure `git_workflow.svg`, whose repository URLs are Jinja placeholders.
It can still be edited in Inkscape, which keeps the placeholders as plain text.
The installments of the training are defined in
[`handson/.template/installments.toml`](handson/.template/installments.toml),
which sets the audience and the sandbox repository of each installment.
For every installment, the workflow writes the rendered tutorials into `handson/<installment>/`.
These rendered files are committed to Git, so that participants can read them on GitHub.
Do not edit them directly: change the templates and rerun the workflow instead.

## Requirements

- [Typst](https://typst.app/) (version 0.15.1) must be installed.

- [uv](https://docs.astral.sh/uv/) is used to create a Python virtual environment with StepUp.

- The slides use the fonts Source Sans 3, Source Code Pro and Erewhon Math,
  which can be downloaded from the sites listed in the
  [UGentish README](https://github.com/reproducible-reporting/ugentish#fonts).

- The slides use the [UGentish](https://github.com/reproducible-reporting/ugentish) Typst packages
  (`@ugentish/animo-ugentish`, `@ugentish/ugentish`) for the look and feel.
  This is an unofficial style, loosely based on the UGent style guide.
  It is not available on Typst Universe (yet),
  so it must be cloned into the git-ignored `.typst-packages/` directory of this repository:

  ```bash
  git clone --depth 1 \
    https://github.com/reproducible-reporting/ugentish.git \
    .typst-packages/ugentish
  ```

  The workflow passes `--package-path=.typst-packages/ugentish/typst/packages` to Typst.
  Other packages, such as [Animo](https://github.com/reproducible-reporting/animo),
  are downloaded automatically by Typst from Typst Universe.

## Running the workflow

Create the Python virtual environment in `.venv/` with StepUp and other dependencies
from [`pyproject.toml`](pyproject.toml):

```bash
uv sync
```

Then activate the environment and run the workflow:

```bash
source .venv/bin/activate
stepup build
```

(Alternatively, run `uv run stepup build` without activating the environment.)
After changing the slides or the templates, run `stepup build` again:
StepUp only reruns the steps whose inputs have changed.
With `stepup build --watch`, StepUp keeps watching for changes after the build,
and pressing `r` rebuilds the outdated outputs.

Notes:

- To preview the slides with Tinymist in VS Code,
  set the environment variable `TYPST_PACKAGE_PATH="${PWD}/.typst-packages/ugentish/typst/packages"`
  and start VS Code from that shell.
- The workflow in [`.github/workflows/publish.yaml`](.github/workflows/publish.yaml)
  performs the same steps as above, including the font installation, on a clean Ubuntu machine.
  It also verifies that the committed tutorials are up to date with their templates.
  When a tag starting with `v` is pushed, the slides are published as a GitHub release.

## Setting up a sandbox repository

Each installment needs its own sandbox repository, which participants fork during the hands-on tutorial.
Its initial contents are in the [`sandbox/`](sandbox/) directory of this repository.
The files `animals.md` and `foods.md` in this directory are generated by the workflow,
so make sure they are up to date by running `stepup build` first.

1. Create a new repository on the GitHub instance used by the participants, e.g.
   <https://github.ugent.be/new> for Ghent University.
   (The participants' accounts must exist on this instance, so it is not necessarily `github.com`.)

   - Choose an owner (your account or an organization) and a name, e.g. `sandbox-2026`.
   - Make sure all participants can read the repository,
     but do not give them write access: they must fork it.
   - Do not add a README, `.gitignore` or license file, so that the repository is created empty.

1. Add the installment to [`handson/.template/installments.toml`](handson/.template/installments.toml)
   with the URL of the new repository, and run `stepup build` to render its tutorials.

1. Make a copy of the `sandbox/` directory outside this repository,
   and turn it into a new Git repository with a single initial commit:

   ```bash
   cp -r sandbox ../sandbox-2026
   cd ../sandbox-2026
   git init
   git add .
   git commit -m "Initial commit"
   ```

1. Rename the current branch to `main`, configure the new repository as `origin`, and push:

   ```bash
   git branch -M main
   git remote add origin git@github.ugent.be:SciCompPhys/sandbox-2026.git
   git push -u origin main
   ```

   Replace the URL with the SSH (or HTTPS) URL of your new repository,
   which is shown on its (empty) page on GitHub.
